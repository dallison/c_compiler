# 6502 and 65C02

DaveCC compiles hosted C and C++ for the MOS 6502 and WDC 65C02 and runs the
result in the in-tree `6502` interpreter (or, with the same ABI, on matching
hardware plus the support ROM). There is no Linux profile. Images are always
static ELF; `-fPIC`, `-shared`, and `-dynamic` are rejected.

`-target 6502` and `-target 65c02` share one data model, one zero-page ABI,
one guest archive (`libc65c02.a`), and one interpreter. The difference is
the instruction set: 65C02 codegen may emit `BRA`, `STZ`, `INA` / `DEA`,
`PHX` / `PHY` / `PLX` / `PLY`, and zero-page indirect `(zp)` without an
index register. NMOS 6502 codegen stays on the original opcode set (`JMP`
instead of `BRA`, `(zp),Y` instead of `(zp)`, and so on).

The runnable profile is **65C02**. Build the compiler, guest archive, ROM,
and interpreter, then link at `_start` (do not override the entry point to
`main`):

```sh
bazelisk build //:davecc //:libc_65c02 //:6502 //:support_rom_65c02
bazel-bin/davecc -target 65c02 program.c -o program
bazel-bin/6502 -rom bazel-bin/6502_support/6502rom.exe program
```

The interpreter looks for the ROM via `-rom`, `DAVECC_6502_ROM`, or the
usual Bazel / install paths. Both targets default to `-O2` and optimize for
size. Each function is emitted in its own ELF section so `--gc-sections`
can drop unused libc and runtime helpers.

## Data model

| Type | Size | Notes |
| --- | --- | --- |
| `char` / `bool` | 8 bits | Plain `char` is unsigned |
| `short` / `int` / pointers / `size_t` | 16 bits | `INT_MAX` is 32767 |
| `long` / `float` | 32 bits | `long` is the 32-bit integer type |
| `long long` | 64 bits | Software arithmetic |
| `double` / `long double` | 32 bits | Same representation as `float` |
| `wchar_t` | 16 bits | |
| Aggregate / stack alignment | 1 byte | No padding for alignment |

IEEE-754 **binary32** (single precision) is implemented in software and is
the only floating format. `float`, `double`, and `long double` are all
24-bit significand / 8-bit exponent numbers. True binary64 is not
supported: a 64-bit mantissa and exponent pair would consume too much of
the 64 KiB address space and is far too slow on an 8-bit ALU. C++23
`std::float64_t` / `1.0f64` is diagnosed at compile time. Soft-float
helpers live in `6502 support/fadd.s`, `fmul.s`, `fdiv.s`, `fneg.s`,
`fcmp.s`, and `fconv.s`; they unpack to a 40-bit mantissa plus separate
sign and exponent in zero-page scratch (`0xa2`–`0xba`).

## Limitations

**No threads.** The 6502 has one set of registers, no privileged mode, and
no timer interrupt that DaveCC uses as a scheduler. The interpreter is a
single host thread that steps one guest instruction at a time. There is
therefore no clone/futex surface, no TLS, and no heap lock. C11
`<threads.h>` and C++ `<thread>`, `<stop_token>`, `<condition_variable>`,
`<semaphore>`, `<latch>`, and `<barrier>` are compile-time errors. C11
defines `__STDC_NO_THREADS__`.

**No atomics.** The ISA has no compare-and-swap or locked read-modify-write
that could implement `_Atomic` or `std::atomic` correctly, even for a
single thread that might later grow interrupts. Including `<stdatomic.h>`
or `<atomic>`, or using a compiler atomic builtin, is diagnosed. C11
defines `__STDC_NO_ATOMICS__`. The builtins that *are* available, including
the 6502 ctype / `memcpy` helpers, are listed in [builtins.md](builtins.md).

**No C++ exceptions.** Exception tables, a DWARF / LSDA personality, and a
throw/unwind runtime are too large for a 64 KiB address space that already
holds the program, the heap, and the software stack. Both targets default
to `-fno-exceptions`. `-fexceptions` turns the frontend syntax back on,
but the backend still does not emit unwind metadata, a frame walker,
landing-pad transfer, or `__cxa_throw`. Tests and libraries must use
`__cpp_exceptions` when an exception-dependent path has an exception-free
alternative. C++20 coroutines work in this profile; only the
throw / unhandled-exception branches are absent.

Other hard limits:

- 64 KiB total address space. The linker rejects a program whose image
  grows past `0xbe00`, leaving a minimum software-stack reserve under the
  ROM.
- Ten host files (stdin / stdout / stderr plus seven `open` slots).
- `FILENAME_MAX` is 16; stdio buffers default to 64 bytes.
- No hosted `malloc` / `free` / `realloc` syscalls. The guest first-fit
  allocator owns the RAM between `_end` and the software stack.
- `environ` is a guest pointer. The interpreter does not copy the host
  environment in; `getenv` only sees what the program stores there.
- RTTI uses DaveCC's compact layout, not the Itanium ABI.
- Shared libraries, PIC, TLS, and lazy binding do not exist.

## Zero-page registers

The 6502 has A, X, Y, S, and P. DaveCC treats the bottom of zero page as a
fixed register file that both the compiler and `libc65c02.a` assemble
against. Addresses `0x00`–`0xba` are the C ABI; `0xbb`–`0xff` are reserved
for the ROM and interrupt scratch.

Callee-saved counts are the high-numbered registers of each class
(12 of 16 `i` registers, 6 of 8 `b` and `l`, 3 of 4 `x` and `f`). The
first registers of each class are temporaries clobbered by calls.

| Addresses | Name | Width | Role |
| --- | --- | --- | --- |
| `0x00`–`0x07` | `b0`–`b7` | 8 bits | Bytes / `char` / `bool` |
| `0x08`–`0x27` | `i0`–`i15` | 16 bits | `int`, pointers, `size_t` |
| `0x28`–`0x47` | `l0`–`l7` | 32 bits | `long` |
| `0x48`–`0x67` | `x0`–`x3` | 64 bits | `long long` |
| `0x68`–`0x77` | `f0`–`f3` | 32 bits | `float` / `double` (same slots) |
| `0x78`–`0x79` | `__sp` | 16 bits | Software stack pointer (next free byte) |
| `0x7a`–`0x7b` | `__fp` | 16 bits | Frame pointer |
| `0x7c`–`0x7d` | `__result` | 16 bits | Address of the caller's result slot |
| `0x7e`–`0x81` | `__t0`–`__t3` | 8 bits | Runtime temps |
| `0x82`–`0xa1` | `mt1`–`mt3`, `__mem_*` | | Integer mul/div and `memcpy` scratch (overlap) |
| `0xa2`–`0xba` | float scratch | 24 bytes | Unpacked mantissa / exponent / sign |
| `0xbb`–`0xfc` | OS scratch | | ROM and device state |
| `0xfd`–`0xff` | IRQ scratch | | Saved A and the BRK-operand pointer |

`i0` is also the startup argc register: the interpreter writes guest
`argc` there after constructors run, and `_start` pushes it for `main`.
A function that returns a value is entered with X/Y holding the address of
the destination (usually a zero-page register). That pointer is stored in
`__result` and, for non-leaf calls, saved in the frame.

## Support library and calling convention

`libc65c02.a` is two layers packed into one archive.

The **compiler support library** is the assembly in `6502 support/`. The
backend emits `JSR` to these helpers instead of inlining every 16- and
32-bit operation:

| Files | Purpose |
| --- | --- |
| `start.s` | `_start`: set `__sp`/`__fp` to `0xc000`, push argv/argc, `JSR main`, `exit` |
| `enter.s` | `__enter` / `__leave` (and leaf / no-mask / result variants) |
| `var_addr.s`, `var_value.s` | Address and load/store of frame locals and incoming args |
| `push.s`, `pull_drop.s`, `pushmem.s` | Software-stack push/pop, including whole registers |
| `frame_push.s`, `inline_mem_params.s` | Outgoing argument setup |
| `load_indirect.s`, `store_indirect.s` (and `*8`) | Load/store through a zero-page pointer |
| `copymem.s`, `zeromem.s` | Block copy and zero |
| `spill.s` | Spill / reload when the register file is exhausted |
| `mul.s`, `longmul.s`, `longlongmul.s` | 8/16/32/64-bit multiply |
| `div.s`, `longdiv.s`, `longlongdiv.s` | Signed and unsigned divide / remainder |
| `incdec.s` | Wide increment and decrement |
| `jump_table.s`, `jmpi.s` | `switch` and indirect call |
| `fcommon.s`, `fadd.s`, `fmul.s`, `fdiv.s`, `fneg.s`, `fcmp.s`, `fconv.s` | IEEE-754 binary32 |
| `syscall.s` | C `syscall()` trap (`LDA #n` / `$EF`) |
| `setjmp.s` | `setjmp` / `longjmp` (callee-saved ZP regs, `__sp`/`__fp`, hardware S, return PC) |
| `intrinsic.s`, `stacktrace.s` | Compiler intrinsics and a compact backtrace |

The **C and C++ library** is the usual DaveCC guest libc, compiled
`-target 65c02`. What you actually get:

- **C:** `<stdio.h>` (64-byte buffers), `<stdlib.h>` (first-fit
  `malloc`/`free`/`realloc`/`calloc`, `qsort`, `bsearch`, `strto*`),
  `<string.h>` / `<strings.h>`, `<ctype.h>`, `<math.h>` and `<complex.h>`
  on binary32, `<time.h>` via host clocks, POSIX `open`/`close`/`read`/
  `write`/`lseek`, `<setjmp.h>`, in-process `<signal.h>` (`raise` only),
  `<wchar.h>` / `<wctype.h>` / `<uchar.h>`, C locale, `printf` / `scanf`
  (the driver specializes `printf` by default on these targets).
- **C++20:** containers, `<string>`, iostreams, `<format>`, `<chrono>`,
  `<filesystem>`, `<random>`, and exception-free coroutines. `new` uses
  the guest heap. Threading and atomic headers do not compile. Exception
  types exist as declarations; throwing is not supported.

### Software stack and frames

Arguments are pushed right-to-left onto the **software** stack (`__sp`),
not the 256-byte 6502 page-1 stack. After the arguments, X/Y hold the
result address and the callee is entered with `JSR`. A fixed-arity
non-void, non-struct function pops its own arguments on return; `void`,
varargs, and struct-return calls are caller-cleaned.

`__enter` allocates the frame, stores a 24-bit callee-save mask, spills
the registers named by that mask, and saves the old `__fp` and (for
non-leaf functions) `__result`. Locals sit below the frame pointer and
are addressed as `fp - offset`. Leaf functions that need no saved
registers use the `*_nomask` / `*_leaf` variants.

```
+--------------------+
|    previous frame  |
+--------------------+  <- incoming __sp, new __fp
|  save mask (3)     |  <- omitted when the mask is zero
+--------------------+
|  locals            |  <- accessed as (__fp) - offset
+--------------------+
|  spilled regs      |
+--------------------+
|  saved __result    |  <- non-leaf only
+--------------------+
|  saved __fp        |
+--------------------+  <- current __sp
```

The **hardware** stack at `0x0100`–`0x01ff` (register S) is only for
`JSR`/`RTS`, `PHA`/`PLA` (and 65C02 `PHX`/`PHY`), and the IRQ/BRK frame
(P, PC). It is not the C stack. Crossing those 256 bytes corrupts return
addresses; deep C recursion exhausts the software stack first and collides
with the heap.

### Heap

`malloc` is a compact first-fit list, not a host syscall. On the first
allocation it claims every byte from the ELF `_end` symbol up to
`0xc000` (the software-stack base) as one free block. Allocated blocks
are a 16-bit payload length followed by the payload. `free` inserts by
address and coalesces neighbours. When the list cannot satisfy a request,
`malloc` returns `NULL`. The heap grows toward higher addresses; the
software stack grows toward lower ones. When they meet, the process is
out of memory.

## Memory map

The interpreter gives the guest a flat 64 KiB. The support ROM is loaded
from `6502rom.exe` into the top of that space; the program ELF is copied
over the low RAM. Memory-mapped I/O at `0xfe00` overlays the ROM image.

```
0xffff +----------------------+
       | IRQ/RESET/NMI        |  0xfffa–0xffff   hardware vectors
0xfffa +----------------------+
       | reset / IRQ / boot   |  0xff00–0xfff9   ROM (SEI, TXS, setup_fds)
0xff00 +----------------------+
       | ACIA (console)       |  0xfe00 CSR, 0xfe01 data
0xfe00 +----------------------+
       | support ROM          |  0xc000–0xfdff   helpers, BRK dispatch
0xc000 +----------------------+  <- software stack base (__sp / __fp)
       | software stack |     |  grows down
       |                v     |
       |                      |
       |                ^     |
       | guest heap     |     |  grows up from _end
       +----------------------+  <- _end (first byte after .bss)
       | .bss / .data         |
       | .text / .rodata      |  program image (static ELF)
0x0800 +----------------------+
       | argv[] + strings     |  0x0500–0x07ff
0x0500 +----------------------+
       | reserved             |  0x0400–0x04ff
0x0400 +----------------------+
       | fd table (10 × 4)    |  0x03d8–0x03ff
       | errno (int16)        |  0x03d6
       | reserved             |  0x0200–0x03d5
0x0200 +----------------------+
       | 6502 hardware stack  |  0x0100–0x01ff   register S
0x0100 +----------------------+
       | zero-page registers  |  0x0000–0x00ba   C ABI
       | OS / IRQ scratch     |  0x00bb–0x00ff
0x0000 +----------------------+
```

Startup:

1. The interpreter maps the ROM, copies the program, runs
   `.preinit_array` / `.init_array`, then writes argv into `0x0500`–`0x07ff`
   and `argc` into `i0`.
2. It stores the ELF entry (`_start`) at `0x0000`/`0x0001` and jumps
   through the RESET vector (`0xfffc`).
3. The ROM reset stub sets S to `$FF`, builds the three standard file
   descriptors, clears `errno`, and `JMP ($0000)` into `_start`.
4. `_start` points `__sp` and `__fp` at `0xc000`, pushes argv and argc,
   calls `main`, and `exit`s (atexit + stdio flush, then the exit
   syscall).

## System calls

C `syscall(int n, ...)` is implemented in `6502 support/syscall.s`. It
rewrites the software-stack slot that held `n` into the address of the
four-byte `long` result, then executes an undefined 65C02 opcode `$EF`.
The interpreter treats `$EF` as a software break: A is the call number,
`(__sp)` is the result address, and packed arguments start at
`(__sp)+2`. Pointers, `int`, and `size_t` are two bytes; the host writes
a 32-bit signed result through the result pointer and also leaves the
low 16 bits in X/Y.

`SYS_EXIT` is **1** and `SYS_ABORT` is **8** on this target (not the
generic DaveCC 12 / 11). Thread, TLS, and host-heap numbers are not
defined. Unknown numbers return `-ENOSYS`. Failed host I/O stores a
translated `errno` at `0x03d6`.

| Number | Name | What the interpreter does |
| --- | --- | --- |
| 1 | `SYS_EXIT` | Host `exit(status)` |
| 2 | `SYS_OPEN` | Host `open`; guest fd is an index into a 10-slot table (0–2 are stdin/stdout/stderr) |
| 3 | `SYS_CLOSE` | Host `close` |
| 4 | `SYS_WRITE` | Host `write` |
| 5 | `SYS_READ` | Host `read` |
| 7 | `SYS_LSEEK` | Host `lseek` |
| 8 | `SYS_ABORT` | Dump PC / software SP / hardware S and abort |
| 13 | `SYS_TIME` | Host calendar time |
| 14 | `SYS_CLOCK` | Host `CLOCK_PROCESS_CPUTIME_ID` |
| 22 | `SYS_EXIT_CLEAN` | Record the status, run `.fini_array`, stop the interpreter |
| 24 | `SYS_MONOTONIC_TIME` | Host `CLOCK_MONOTONIC` in microseconds |
| 30 | `SYS_REALTIME_TIME` | Host `CLOCK_REALTIME` in microseconds |
| 31–48, 61 | `SYS_FS_*` | Host filesystem (`stat`, directories, rename, symlink, space, canonical path, …) |
| 49–59 | `SYS_TZDB_*` | Host IANA time-zone database |
| 60 | `SYS_RANDOM_BYTES` | Host CSPRNG |

A second, narrower path exists for a hardware `BRK`: the ROM IRQ stub
reads the signature byte after `BRK` and dispatches a table of
`exit` / `open` / `close` / `write` / `read` / `lseek` / `abort`. Guest
C and C++ do not use that path; they go through `$EF`.

The ROM also owns a tiny device table used by the BRK helpers: stdin and
stdout talk to the ACIA at `0xfe00`/`0xfe01` (the interpreter maps those
bytes onto host stdin/stdout), and further descriptors are ordinary host
files. `libc` I/O uses the `$EF` calls above, so `printf` and `fopen`
never touch the ACIA registers directly.
